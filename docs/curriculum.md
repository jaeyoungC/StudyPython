# 전체 커리큘럼 — 초급 아키텍트를 위한 소프트웨어 엔지니어링 기초

학습 노트 [Andrew Ng: 코딩은 더 이상 병목이 아니다](https://claude.ai/artifact/TYZGvjwyDU6SfNaraeA1vp)가 말하는 범위를
빠짐없이 다루는 것을 목표로 합니다. 시간표가 아니라 **지도**입니다. 한 단원에 사흘이 걸려도, 삼 주가 걸려도 괜찮습니다.
끝낸 단원은 노트의 로드맵 표에서 상태를 바꾸세요.

## 설계 원칙

1. **하나의 프로그램을 끝까지 키운다.** 3단원에서 만든 "할 일 관리" 프로그램이 54단원까지 이어집니다.
   메모리 → 클래스 → 파일 → SQLite → 계층 분리 → HTTP API → 인증·캐시·비동기 → 서비스 분리 → 신뢰성 장치 →
   관측·배포·확장 → 에이전트가 호출하는 시스템 → LLM 기능 → 사용자가 원하는 기능.
2. **새 개념은 한 번에 하나씩.** 한 단원이 소개하는 새 문법·도구는 2~3개를 넘지 않습니다. 시작 코드와 테스트에
   쓰인 것은 모두 그 단원이나 앞 단원에서 설명합니다.
3. **먼저 내 답, 그다음 AI.** 모든 단원에 "스스로 답해 볼 질문"이 있고, `CLAUDE.md`의 튜터 모드가 정답을 바로 주지 않습니다.
4. **결정은 기록한다.** 설계 선택이 있는 단원은 ADR을 남깁니다. 단원이 쌓일수록 과거의 나와 대화하게 됩니다.
5. **노트의 "4대 스킬"을 모두 다룬다.** ② 소프트웨어 기초(1~5단계), ③ 코딩 에이전트(6단계), ① AI 기본 요소(7단계),
   ④ 빌드 방향 잡기(8단계 + 모든 단원의 의식).

## 모든 단원에서 반복하는 의식

| 의식 | 언제부터 | 하는 일 |
| --- | --- | --- |
| 내 답 먼저 | 1단계 | 질문에 내 결론과 이유를 `NOTES.md`에 쓴 뒤 AI와 비교 |
| NOTES.md | 1단계 | 배운 것 3가지 / 헷갈린 것 1가지 / 다음 단원에 바꿀 것 |
| 브랜치 → PR → 머지 | 1단원 | 단원마다 브랜치를 만들고 PR로 스스로 리뷰한 뒤 머지 |
| ADR | 7단원 | 설계 선택이 있던 단원은 `docs/adr/`에 결정 기록 |
| 세 문장 설명 | 7단원 | 이번 단원의 결정 하나를 비개발자에게 세 문장으로 설명해 `NOTES.md`에 적기 |
| AI 코드 리뷰 | 8단원 | 내 코드를 AI에게 리뷰받고, 지적 중 하나를 골라 반영하고 하나는 반박해 보기 |
| 에이전트에게 작은 과제 | 15단원 | 단원 과제 중 작고 검증 가능한 것 하나를 노트의 체크리스트대로 에이전트에게 맡기고 검토 |
| 사용자에게 보여 주기 | 각 단계 끝 | 가족·친구 1~2명에게 프로그램을 보여 주고 "가장 불편한 점" 한 줄 받기 |
