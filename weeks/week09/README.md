# 9주차 — 테스트 전략 · 타임아웃 · 재시도 · 멱등성

## 목표

노트의 질문 "외부 API가 멈추면 사용자는 무엇을 보게 되는가?"에 코드로 답합니다.

## 공부할 개념

- 테스트 피라미드: 단위 테스트와 통합 테스트의 비율, 무엇을 가짜(mock)로 바꾸는가
- 타임아웃: 타임아웃 없는 네트워크 호출이 왜 위험한가
- 재시도: 지수 백오프(exponential backoff) + 지터(jitter), 재시도하면 안 되는 오류
- 멱등성(idempotency): 같은 요청이 두 번 와도 결과가 한 번과 같게 — `Idempotency-Key` 헤더

## 과제

1. 일부러 느리고 가끔 실패하는 "가짜 알림 서비스"를 만들기 (예: 30% 확률로 500, 가끔 3초 지연)
2. 할 일을 완료하면 알림을 보내는 기능: 타임아웃 1초, 최대 3회 재시도
3. `POST /tasks` 에 `Idempotency-Key` 를 지원해서, 같은 키로 두 번 보내도 할 일이 하나만 생기게 하기
4. 시간과 무작위성을 주입해 테스트가 항상 같은 결과를 내게 만들기

## 스스로 답해 볼 질문

1. 알림 전송이 실패하면 할 일 완료도 실패해야 할까요? (노트: 점진적 기능 저하)
2. 코딩 에이전트가 같은 요청을 재시도할 때 멱등성이 없으면 어떤 사고가 날까요?
