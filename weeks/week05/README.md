# 5주차 — 접근 패턴 · 정규화 · 인덱스

## 목표

노트에서 "되돌리는 비용이 가장 큰 결정"이라고 한 데이터 모델을 연습합니다. 할 일에 태그를 붙이는 기능을 추가하며
"가장 자주 일어나는 조회는 무엇인가?"부터 정합니다.

## 공부할 개념

- 접근 패턴(access pattern): 어떤 조건으로, 얼마나 자주 읽고 쓰는가
- 정규화: 1:N, N:M 관계, 연결 테이블(`task_tags`), 외래 키(FOREIGN KEY)
- `JOIN`, `GROUP BY`, `COUNT`
- 인덱스: `CREATE INDEX`, `EXPLAIN QUERY PLAN` 으로 인덱스를 쓰는지 확인

참고: 『데이터 중심 애플리케이션 설계』 2~3장 (노트에서 추천한 기본서)

## 과제

1. 코드를 쓰기 전에 `NOTES.md` 에 접근 패턴 3가지를 적기 (예: "태그별 미완료 할 일 보기 — 하루 수십 번")
2. `tags`, `task_tags` 테이블 추가, "태그로 할 일 찾기" 구현
3. 할 일 10만 개를 넣고, 인덱스 전·후로 같은 조회 시간을 `time.perf_counter()` 로 재서 표로 남기기

## 스스로 답해 볼 질문

1. 태그를 `tasks` 테이블에 `"python,sql"` 같은 문자열 한 칸으로 넣으면 어떤 조회가 어려워지나요?
2. 인덱스를 모든 열에 걸면 왜 안 될까요? (쓰기 비용)
