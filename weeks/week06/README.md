# 6주차 — 트랜잭션 · 동시성 · 마이그레이션

## 목표

"이 스키마는 나중에 바꾸기 얼마나 어려운가?"를 직접 체감합니다. 데이터를 잃지 않고 스키마를 바꾸는 법을 익힙니다.

## 공부할 개념

- 트랜잭션: `BEGIN / COMMIT / ROLLBACK`, `with conn:` 블록, 원자성
- 동시성: 두 프로세스가 같은 행을 바꿀 때 생기는 문제 (lost update), SQLite 잠금
- 마이그레이션: 버전 번호를 가진 SQL 파일을 순서대로 적용, `PRAGMA user_version`

## 과제

1. "할 일 옮기기" (한 태그에서 지우고 다른 태그에 붙이기)를 트랜잭션으로 구현하고, 중간에 예외를 일부러 내서 롤백되는지 테스트
2. `migrations/001_init.sql`, `002_add_due_date.sql` 을 만들고, 이미 데이터가 있는 DB에 적용하는 `migrate()` 함수 작성
3. 마이그레이션 전에 백업하고 복구하는 연습 (노트 체크리스트: "백업과 복구 연습")

## 스스로 답해 볼 질문

1. 코딩 에이전트에게 "due_date 열 추가해줘"라고만 하면 기존 데이터는 어떻게 될까요? 스펙에 무엇을 적어야 할까요?
2. 열 이름 바꾸기와 열 추가 중 어느 쪽이 더 위험한가요?
