# 7주차 — 계층 분리와 상태의 위치

## 목표

지금까지 만든 JSON 저장소와 SQLite 저장소를 같은 인터페이스 뒤에 숨기고, 비즈니스 규칙과 저장 방식을 분리합니다.
노트의 "시스템 분해와 상태의 위치"를 작은 규모로 연습합니다.

## 공부할 개념

- 계층: 화면(CLI/API) → 서비스(규칙) → 저장소(repository)
- `typing.Protocol` 로 인터페이스 정의, 의존성 주입(생성자로 저장소 넘기기)
- 상태는 어디에 두는가: 메모리 / 파일 / DB, 그리고 "진실의 원천(source of truth)"
- 테스트 대역(fake): 테스트에서는 메모리 저장소를 주입

## 과제

1. `TaskRepository` Protocol과 `JsonTaskRepository`, `SqliteTaskRepository` 구현
2. `TaskService` 가 저장소 종류를 모른 채 동작하도록 만들기
3. 같은 서비스 테스트를 두 저장소로 모두 돌리기 (`pytest.mark.parametrize`)
4. 그림 한 장: 계층과 호출 방향을 `NOTES.md` 에 그리기 (손그림 사진도 OK)

## 스스로 답해 볼 질문

1. "빈 제목 금지" 규칙은 어느 계층에 있어야 하나요? DB의 `CHECK` 제약에도 있어야 하나요?
2. 이 구조는 프로토타입에는 과잉 설계일까요? 노트의 "프로젝트 단계별 아키텍처" 관점에서 답해 보세요.
