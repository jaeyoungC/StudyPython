# 10주차 — 속도 제한 · 점진적 기능 저하 · 일부러 고장 내기

## 목표

노트 학습법 5번 "일부러 고장 내 보기"를 실천합니다. 시스템이 어떻게 무너지는지 보고, 무너지는 범위(blast radius)를 줄입니다.

## 공부할 개념

- 속도 제한(rate limit): 토큰 버킷 알고리즘, `429 Too Many Requests`, `Retry-After`
- 점진적 기능 저하(graceful degradation): 부가 기능이 죽어도 핵심 기능은 유지
- 서킷 브레이커(circuit breaker) 개념
- 피해 범위 최소화: 에이전트용 읽기 전용 계정, 최소 권한

## 과제

1. 토큰 버킷 rate limiter를 직접 구현하고 테스트 (시간을 주입해서)
2. API에 적용: 클라이언트별 분당 60회
3. 장애 실험 3가지를 하고 표로 기록: 알림 서비스 중단 / DB 파일 읽기 전용 / 요청 폭주
   (실험 | 예상 | 실제 결과 | 고친 것)
