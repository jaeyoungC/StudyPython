# ADR-0016: 확장 단계의 할 일 서비스 아키텍처

- 날짜: YYYY-MM-DD
- 상태: 제안 / 채택
- 시나리오: **확장** — 사용자 수만 명, 에이전트가 API 를 사람보다 10배 많이 부른다. 팀이 3~5명이고 알림 기능은 다른 사람이 맡는다. 장애 한 시간이 돈으로 환산된다.

## 맥락

이 단계에서 가장 비싼 것은 **장애와 팀의 조율 비용**입니다. 이제야 22단원의 분리, 37단원의 수평 확장이 값을 합니다. 그러나 전부 한꺼번에 하면 안 됩니다. 무엇부터, 어떤 숫자를 보고.

- 지연 · 비용 · 일관성 요구 (기능별로 다르게 적어도 된다):
