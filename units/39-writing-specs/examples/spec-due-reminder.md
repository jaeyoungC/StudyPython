# 스펙: 마감 하루 전 알림 (예시)

- 작성일: 2026-11-02 / 작성자: 학습자
- 프로젝트 단계: **운영 중** (가족 3명이 35단원 배포본을 실제로 씀)
- 관련 ADR: ADR-00xx (알림 서비스 분리, 22단원), ADR-00xx (`due` 열 추가, 12단원)
- 상태: 확정

## 0. 세 줄 질문

| 질문 | 답 |
| --- | --- |
| 누가, 얼마나 많이 쓰는가 | 사용자 3명, 마감일 있는 할 일 하루 평균 5건, 알림은 하루 5~10건 |
| 지연·비용·일관성 중 무엇을 우선하는가 | **일관성**(같은 할 일에 알림 2번 금지) > 비용(무료 호스팅 범위) > 지연(±5분 허용) |
| 되돌리기 어려운 결정은 무엇인가 | "알림을 보냈다"는 사실을 어디에 기록하는가. 한 번 `notified_at` 열로 정하면 나중에 "알림 여러 번" 기능 때 테이블을 쪼개야 함 → 처음부터 `reminders` 테이블로 분리 |

## 1. 목표

사용자가 마감일을 넣어 두면 마감 24시간 전에 알림을 한 번 받는다.

## 2. 하지 않는 것

- 알림 시각 사용자 설정 (항상 24시간 전)
- 이메일·푸시 등 새 채널 (22단원 notifier 서비스의 기존 채널만)
- 화면 변경

## 3. 요구사항

| # | 요구사항 | 확인 방법 |
| --- | --- | --- |
| R1 | `due`가 있고 `done=False`인 할 일은 `due - 24h` 시각 ±5분 안에 알림이 1건 생성된다 | `test_reminder_created_24h_before_due` |
| R2 | 같은 할 일에 알림은 최대 1건이다 (워커가 두 번 돌아도) | `test_reminder_is_idempotent_per_task` |
| R3 | 알림 전에 완료되면 알림을 보내지 않는다 | `test_no_reminder_for_completed_task` |
| R4 | 마감일을 바꾸면 이전 예약은 취소되고 새 시각으로 다시 잡힌다 | `test_due_change_reschedules_reminder` |

| 상황 | 기대 동작 |
| --- | --- |
| notifier 서비스가 5초 안에 응답하지 않음 | 알림은 큐에 남고 다음 주기에 재시도 (25단원 백오프, 최대 3회), 완료 처리는 영향 없음 |
| 서버가 24시간 넘게 꺼져 있었음 | 지나간 알림은 보내지 않고 로그에 `reminder_skipped_stale` 남김 |

## 4. 완료 기준

- [ ] R1~R4 테스트 통과, 기존 테스트 유지
- [ ] 배포 후 24시간 안에 `/metrics`의 `reminders_sent_total`이 증가하고 `reminders_duplicate_total`이 0

## 5. 기술 설계

- 바뀌는 모듈: `todo/worker.py`(주기 작업 추가), `todo/service.py`(마감 변경 시 재예약), 새 `todo/reminders.py`
- 데이터: 마이그레이션 `004_reminders.sql` — `reminders(task_id PK, scheduled_at, sent_at NULL)`
- API: 변화 없음
- 외부 호출: notifier `POST /notify` 타임아웃 5초, 재시도 3회, 서킷 브레이커(28단원) 공유
- 성능: 워커 1분 주기, 쿼리는 `due` 인덱스(10단원) 사용

## 6. 아키텍처 영향

- 알림 서비스 분리 ADR과 일치 (알림 전송은 notifier만)
- 계층 규칙: 예약 로직은 서비스 계층, 시각 비교는 주입된 `clock` 사용 (테스트 가능)
- 권한: 워커는 `reminders`와 `tasks` 읽기, `reminders` 쓰기만
- 되돌리기: 피처 플래그 `REMINDERS_ENABLED`(36단원). 끄면 테이블은 남고 워커만 멈춤

## 7. 에이전트에게 맡길 때의 지시

1. 마이그레이션 파일과 `reminders.py`의 순수 함수(`next_reminder_time(due, now)`)부터 → 테스트 R1
2. 멱등 삽입(`INSERT ... ON CONFLICT DO NOTHING`) → 테스트 R2
3. 서비스 연결 → R3, R4
4. 워커 연결은 내가 직접 (외부 호출이 있으므로)

- 건드리지 말 것: `todo/api.py`, `web/`
- 권한: `data/` 디렉터리 쓰기 금지, 네트워크 호출 금지
- 테스트는 내가 뼈대를 먼저 제공
