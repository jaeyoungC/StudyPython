# 40 — 컨텍스트 파일과 권한

## 목표

내 할 일 프로젝트를 위한 컨텍스트 파일(`CLAUDE.md` / `AGENTS.md`)을 **아키텍처 가정·데이터 접근 패턴·스타일** 중심으로 쓰고,
에이전트에게 줄 권한을 "읽기 / 쓰기 / 실행 / 배포"의 단계로 나누어 운영 데이터가 다치지 않게 만듭니다.

## 노트와의 연결

> "컨텍스트 파일에 코드베이스 정보, 아키텍처 가정, 스타일, 데이터 접근 패턴을 적어 둔다"

체크리스트 "맡기기 전"의 마지막 항목은 **권한 제한**이고, "맡긴 후"의 마지막 항목은 **컨텍스트 파일 갱신**입니다.
인프라 표의 마지막 줄 "최소 권한·읽기 전용·백업"은 30단원에서 사람과 서비스에 적용했습니다. 이번에는 에이전트에 적용합니다.

38단원에서 컨텍스트 파일이 창을 차지한다는 것을 봤습니다. 그러니 컨텍스트 파일은 **매 세션 비용을 내고 넣을 가치가 있는 문장만** 담아야 합니다.

## 공부할 개념

| 개념 | 핵심 | 참고 |
| --- | --- | --- |
| 컨텍스트 파일의 네 가지 내용 | ① 코드베이스 지도(어디에 무엇이, 어떻게 실행·테스트하는가) ② 아키텍처 가정(계층 규칙, 상태의 위치, 서비스 경계) ③ 데이터 접근 패턴(어느 테이블을 누가 어떤 쿼리로, 금지된 접근) ④ 스타일(이름 규칙, 오류 처리, 테스트 규약). 이 저장소의 `CLAUDE.md`에는 ①과 ④만 있습니다 | 이 저장소 `CLAUDE.md`, `docs/project-api.md` |
| 지시의 층위 | 전역(모든 프로젝트) / 프로젝트(저장소 루트) / 디렉터리(하위 폴더) / 세션(프롬프트). 아래 층이 위 층을 덮습니다. **바뀌지 않는 사실은 위에, 이번 작업만의 사실은 아래에** | 38단원 |
| 권한 단계와 승인 지점 | 읽기 → 작업 디렉터리 쓰기 → 명령 실행(테스트) → 네트워크·배포. 되돌릴 수 없는 행동(삭제, 마이그레이션, 배포, 운영 DB 접근) 앞에 사람의 승인을 둡니다. 운영 비밀값은 에이전트 환경에 아예 없게 | 30단원 최소 권한, 29단원 비밀값 |

### 컨텍스트 파일에 넣을 것과 넣지 말 것

| 넣는다 | 넣지 않는다 |
| --- | --- |
| "할 일 규칙(빈 제목·중복 완료·과거 마감)은 `todo/service.py`에만 있다. 리포지토리에 규칙을 넣지 않는다" | 코드를 읽으면 아는 것 (함수 목록) |
| "테스트는 `:memory:` SQLite, 시간은 `clock` 주입. 실제 시간·네트워크 금지" | 세션마다 바뀌는 것 (오늘 할 작업) |
| "`tasks` 테이블은 서비스 계층을 통해서만 접근. `data/prod.db`는 읽기도 금지" | 일반 상식 ("깨끗한 코드를 써라") |
| "오류 응답은 항상 `{"error": {"code", "message"}}`" | 긴 설명 → 링크로 (`docs/project-api.md`) |

### 운영 DB를 보호하는 세 겹

1. **있을 수 없게**: 에이전트 작업 환경에 운영 DB 경로·접속 정보가 없다 (`.env`를 읽지 못하게, 개발용 `.env.example`만)
2. **해도 안 되게**: 읽기 전용 계정(30단원), 쓰기 권한이 필요한 명령(마이그레이션·배포)은 승인 목록
3. **해도 되돌리게**: 백업 검증(12·30단원)이 돼 있고, 롤백 순서(36단원)가 문서에 있다

| E. 효과 측정 | 38단원 과제 C의 모호한 지시를 **새 컨텍스트 파일과 함께** 다시 줍니다. 틀린 가정이 몇 개에서 몇 개로 줄었나요? 컨텍스트 파일의 토큰 수(어림)도 함께 적습니다 | 워크시트 4부 |

## 스스로 답해 볼 질문

1. 컨텍스트 파일에 "함수 목록"을 넣지 않는 이유는 무엇일까요? 넣으면 어떤 일이 생기나요? (코드가 바뀌면)
2. "운영 DB에 접근하지 마라"는 문장을 컨텍스트 파일에 쓰는 것과, 접속 정보를 환경에서 없애는 것 중 무엇이 더 믿을 만한가요? 왜 둘 다 하나요?
3. 튜터 모드 `CLAUDE.md`는 "TODO를 대신 구현하지 마라"고 합니다. 52단원 오너십 프로젝트에서는 이 규칙이 방해가 됩니다. 어느 층위에서 어떻게 덮어써야 할까요?
4. 에이전트가 테스트를 통과시키려고 테스트를 고치는 일을 컨텍스트 파일로 막을 수 있을까요, 권한으로 막아야 할까요?
5. 컨텍스트 파일이 길어질수록 매 세션 비용이 늘고, 짧으면 가정이 늘어납니다. 내 프로젝트에서 적정 길이를 어떻게 정하겠습니까? (과제 E의 숫자)

## 함정

- 소원 목록 쓰기 ("버그 없는 코드를 써라"). 에이전트의 행동을 바꾸지 못하는 문장은 토큰 낭비입니다.
- 코드와 어긋난 채 방치하기. 컨텍스트 파일이 거짓말을 하면 없는 것보다 나쁩니다. 체크리스트 "맡긴 후: 컨텍스트 파일 갱신"을 의식으로 만드세요.
- 권한을 전부 열고 시작하기. "귀찮아서 전부 허용"은 30단원 장애 실험에서 본 그대로 피해 범위를 키웁니다. 처음엔 읽기만, 필요할 때 하나씩.
- 금지만 적기. "무엇을 해도 되는지"가 분명해야 에이전트가 매번 묻지 않습니다. 허용 목록과 금지 목록을 같이.
