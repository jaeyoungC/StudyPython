# 알림 규칙표 (docs/alerts.md 로 복사해 채운다)

원칙: 알림은 **사람이 지금 행동해야 할 때만** 운다. 행동이 없는 알림은 대시보드로 내린다.
각 규칙은 32단원 지표나 31단원 로그 위에 정의하고, 반드시 런북 한 장을 가리킨다.

| 이름 | 조건(지표·기간·임계값) | 심각도 | 누가 받나 / 어떻게 | 런북 | 근거(왜 이 숫자인가) | 마지막 점검 |
| --- | --- | --- | --- | --- | --- | --- |
| 서비스 다운 | `/health` 가 1분간 3회 연속 실패 | 긴급(page) | 나 / 전화·푸시 | RB-01 | 사용자가 아무것도 못 함 | |
| 오류율 높음 | 5xx 비율 > 2%, 5분 지속 | 긴급 | 나 / 푸시 | RB-02 | 30단원 실험 2에서 쓰기 실패가 5xx 였음 | |
| 지연 높음 | p95 > 1s, 10분 지속 | 경고(ticket) | 나 / 다음 날 확인 | RB-03 | 27단원 측정 p95 의 5배 | |
| 알림 발송 정체 | 큐 길이 > 100 또는 브레이커 OPEN 15분 | 경고 | 나 / 다음 날 | RB-04 | 28단원: 알림은 부가 기능 | |
| 속도 제한 급증 | 429 비율 > 20%, 10분 | 정보 | 대시보드만 | — | 에이전트 폭주 가능성. 행동은 사후 분석 | |
| 디스크·DB 파일 | DB 파일 크기 > 80% 한도 | 경고 | 나 | RB-05 | 12단원 백업 용량 | |
| | | | | | | |

## 심각도 정의

| 심각도 | 뜻 | 응답 기대 |
| --- | --- | --- |
| 긴급(page) | 사용자가 핵심 기능을 지금 못 쓴다 | 15분 안에 확인 시작 |
| 경고(ticket) | 지금은 되지만 방치하면 긴급이 된다 | 다음 업무일 |
| 정보 | 알아 두면 좋다 | 대시보드. 알림 보내지 않음 |

## 알림 품질 점검 (매달)

- 지난 달 울린 알림 수: ____ / 그중 실제 행동으로 이어진 수: ____
- 행동 없이 끈 알림(noise)은 임계값을 올리거나 대시보드로 내린다
- 알림 없이 사용자가 먼저 알려 준 장애: ____ → 새 규칙 후보
