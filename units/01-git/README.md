# 01 — git 기초

## 목표

단원마다 "브랜치를 만들고 → 작업하고 → 커밋하고 → PR을 올려 스스로 리뷰하고 → 머지"하는 흐름을 몸에 익힙니다.
앞으로 모든 단원의 완료 기준에 이 흐름이 들어갑니다.

## 노트와의 연결

노트는 운영 영역에 "버전 관리·코드 리뷰·의존성 관리·기술 부채"를 넣었고, 에이전트 워크플로의 마지막 단계로
"CI/CD나 사람의 승인 단계를 거쳐 배포"를 말합니다. PR은 그 승인 단계의 기본 단위이고, 에이전트가 만든 코드를
검토하는 자리도 PR입니다. 에이전트에게 일을 맡기려면 먼저 내가 PR을 읽을 줄 알아야 합니다.

## 공부할 개념

| 개념 | 핵심 | 참고 |
| --- | --- | --- |
| 커밋(commit)과 작업 영역 | 작업 디렉터리 → 스테이지(`add`) → 저장소(`commit`)의 세 단계. 커밋은 "되돌릴 수 있는 저장 지점" | [Pro Git 2장](https://git-scm.com/book/ko/v2/Git%EC%9D%98-%EA%B8%B0%EC%B4%88-Git-%EC%A0%80%EC%9E%A5%EC%86%8C-%EB%A7%8C%EB%93%A4%EA%B8%B0) |
| 브랜치(branch)와 머지(merge) | `main`을 깨끗하게 두고 브랜치에서 작업, 끝나면 합치기. 충돌(conflict)이 무엇인지 | [Pro Git 3장](https://git-scm.com/book/ko/v2/Git-%EB%B8%8C%EB%9E%9C%EC%B9%98-%EB%B8%8C%EB%9E%9C%EC%B9%98%EB%9E%80-%EB%AC%B4%EC%97%87%EC%9D%B8%EA%B0%80) |
| PR(pull request)과 코드 리뷰 | 변경을 설명하고 검토받는 단위. 혼자서도 "리뷰어의 눈"으로 자기 diff를 읽는 연습 | [GitHub PR 문서](https://docs.github.com/ko/pull-requests) |

## 과제

1. **기본 흐름 연습.** 이 저장소에서 다음을 순서대로 합니다.
   ```bash
   git switch -c unit-01-practice
   echo "# 연습" > units/01-git/NOTES.md
   git status                      # 무엇이 바뀌었는지 보기
   git add units/01-git/NOTES.md
   git commit -m "01단원: NOTES 시작"
   git log --oneline -5
   ```
2. **되돌리기 연습.** `NOTES.md`를 일부러 망가뜨린 뒤 `git diff`로 확인하고 `git restore units/01-git/NOTES.md`로 되돌립니다.
   커밋한 뒤에 되돌리고 싶다면? `git revert`와 `git reset`의 차이를 찾아보고 **revert만** 써 봅니다.
3. **충돌 체험.** 브랜치 두 개에서 `NOTES.md`의 같은 줄을 다르게 고치고 머지해 충돌을 일부러 만든 뒤 해결합니다.
4. **PR 흐름.** 브랜치를 GitHub에 올리고(`git push -u origin unit-01-practice`) PR을 만든 뒤, "Files changed" 탭에서
   자기 diff에 댓글을 하나 달아 봅니다(예: "이 줄은 왜 바꿨지?"). 그다음 머지하고 로컬에서 `git switch main && git pull`.
5. **커밋 메시지 규칙 정하기.** 앞으로 쓸 규칙을 `NOTES.md`에 세 줄로 적습니다. 예: 첫 줄은 "무엇을" 50자 이내, 본문은 "왜".

## 스스로 답해 볼 질문

1. 커밋을 "작게 자주" 하면 무엇이 좋고, 무엇이 귀찮아질까요? 적당한 크기는 어떻게 정할까요?
2. 코딩 에이전트가 파일 30개를 한 번에 바꾼 PR을 보냈습니다. 어디서부터 읽어야 할까요?
3. `git push --force`는 왜 위험할까요? 혼자 쓰는 브랜치에서는 괜찮을까요?

## 함정

- `git add .`는 편하지만 `.db`, `.env` 같은 파일이 딸려 들어갑니다. 커밋 전 `git status`를 읽는 습관을 들이세요.
- 머지 충돌 표시(`<<<<<<<`, `=======`, `>>>>>>>`)를 지우지 않고 커밋하면 코드가 깨집니다. 해결 후 테스트를 돌리세요.
- `main`에서 직접 작업하면 되돌리기 어렵습니다. 항상 브랜치부터.

## 완료 기준

- [ ] 브랜치 생성 → 커밋 → push → PR → 셀프 리뷰 댓글 → 머지를 한 번 끝까지 완료
- [ ] 충돌을 한 번 만들고 해결
- [ ] `revert`로 커밋 하나 되돌림
- [ ] `NOTES.md`에 커밋 메시지 규칙 세 줄
